**OCR ARTIFACT WARNING:** Full text from Zotero PDF attachments may be OCR-concatenated in two distinct ways:

- **Words merged without spaces** (e.g., `Thisstudywasdesignedto`) — standard `search_files` heading regex will return 0 results.

- **Character-by-character spacing** (e.g., `T h e n e w e ng l a n d j o u r na l`) — `search_files` will also return 0 results since no heading matches the expected character pattern.

  

If `search_files` finds 0 section headings in Phase 4, try sampling the first 50 lines with `read_file(limit=50, offset=1)`. If the text appears space-separated character-by-character, proceed directly to sequential `read_file` analysis (50-line batches at increasing offsets) to manually locate section boundaries. **Do not spend time tuning heading regex patterns** — the OCR has destroyed the heading structure.

  

As a secondary recovery when `pdftotext` (no `-layout`) produces garbled output: try `pdftotext -layout` which may produce different (sometimes more readable) text on two-column journal article PDFs.

  

**PDF EXTRACTION TOOL HIERARCHY:** When retrieving full text from a local PDF file (not via Zotero MCP), use tools in this order:

  

1. **`pdftotext` (primary — fast, reliable, no timeout risk)**:

- `pdftotext -layout <pdf_path> <output.txt>` — preserves two-column layout but causes bleed-through interleaving of columns on the same lines. **Use this second.**

- `pdftotext <pdf_path> <output.txt>` (no `-layout` flag) — extracts in reading order, no column bleed. **Use this first.** Produces cleaner text for section boundary analysis.

- Both are part of `poppler` utils; typically pre-installed on macOS.

  

2. **`markitdown` (secondary — better column handling but slow)**:

- `markitdown <pdf_path> -o <output.txt>` — slower but handles two-column layouts better.

- **Timeout risk on large PDFs (>5MB)** — times out at 180s default, 600s with explicit timeout. Only use if `pdftotext` produces garbled output.

- If `markitdown` times out, fall back to `pdftotext` without `-layout`.

  

3. **Workflow**: Always try `pdftotext` (no `-layout`) first. Compare a sample (first 100 lines) against the layout version. If the no-layout version has clean sequential text, use it. If it's garbled (e.g., text runs into tables or footnote numbers), try `pdftotext -layout` or `markitdown`.
